If there are outputs in the minicom terminal without doing anything then ModemManager is working disable with the below commands:

sudo systemctl stop ModemManager
sudo systemctl disable ModemManager

sudo systemctl status ModemManager
sudo systemctl restart ModemManager

mmcli -L (shows which modem manager is present)

sudo minicom -D /dev/ttyUSB2 115200    -> at+clanmode?, at+clanmode=0, at+clanmode=1
---------------------------------------------------------------------------------------

If the /dev/ttyUSB* is not itself showing or the lsusb also doesn't show the modem even if the modem is connected then shutdown the Pi completely remove the SIM and brush it clean and insert it then wait a few seconds and power it ON. Then try ping, lsusb, mmcli -m 0 -> these should work.

$ nmcli dev status                // tells us which ones are	 connected to the internet.
$ nmcli connection show

if the gsm module is the primary connection and there is no internet / sim is removed then you can modify the metric so that the wifi is set at a lower metric than gsm (Lower metric = chosed for network than higher metric number)

$ nmcli connection modify "My_WIFI" ipv4.route-metric 100
$ nmcli connection modify "gsm" ipv4.route-metric 600

"Here the My_WIFI and gsm is found by running $ nmcli connection show $ and in this it is the NAME and after this run the below command"

$ nmcli connection up "My_WIFI"
$ nmcli connection up "gsm"     (if you want mobile data as the next preferred data point then do this if not and you only use WIFI then not necessary)

eth0           ethernet  unavailable             --  

-> default via 192.168.225.1 dev usb0  # GSM/SIM
-> default via 10.1.30.1 dev wlan0     # Wi-Fi
- Both were “connected,” but the OS chose the one with the lowest metric (usb0).

- ip route shows routing priority — which interface your system uses to send packets that aren’t for your local network
- even if multiple are connected only the default is providing the internet to the Pi.
